02Protocol

What makes this evaluation strict

  • Untouched finals. Development data guided every change; the final splits were scored exactly once, from frozen code, after the winner was frozen.
  • Preregistration. Hypotheses, success criteria, and analysis plans were recorded in the research map before each run. Failed candidates stay recorded.
  • Exact accounting. Hosted engines get exact attempt ledgers: one HTTP attempt per observation unless recorded otherwise, no partial runs, no retries smuggled into means.
  • Fail-closed coverage. A run that cannot cover every sampled (repo, commit) pair aborts rather than entering a table.
  • Cluster-aware uncertainty. Every paired delta carries a repository-cluster (or case-cluster) bootstrap interval; win claims require the interval to exclude zero.

The systems under test

  • Delphi — this engine. Hybrid retrieval over commit-pinned repository indexes and documentation; exact vector scan, deterministic fusion, attested serving configuration.
  • Hosted engine N — a hosted retrieval+synthesis service with repository and documentation surfaces. Its documentation output is synthesized answer text with citations.
  • Hosted engine C7 — a hosted documentation-only retriever addressed by pinned library IDs.
  • Local baselines — whole-file BM25, the official lexical ranker, and their tuned reciprocal-rank fusion, all over canonical git at the same commits.

Hosted engines are shown by role on charts; full artifact names are in the appendix. The generation model for synthesis stages and downstream evaluation is frozen (…).

04Documentation — the fair ordeal

Hosted engine N returns synthesized answers; scoring those against Delphi's raw retrieved context compares different output contracts. So we matched the contract: every engine's retrieved context goes through the same frozen answer-style synthesis stage, and a no-retrieval control exposes how much of the metric the model earns on its own. 40 development cases, 3 repeats per arm, zero technical failures.
